# New API Statistics 0.1.2

本版本按 New API 渠道标签建立独立的用量、额度和告警账本。仍需已部署、使用 PostgreSQL 的 New API。

## 新功能

- 顶部可切换“全部”、New API 当前使用的各 `channels.tag`、以及“未分组”。所选账本决定用量统计、筛选、排名、明细和 Excel 导出。
- 每个账本分别设置预算、阈值、起始月份和是否启用余额监控；旧版余额设置归入“全部”。飞书、钉钉通知配置仍全局共用。每天北京时间 10 点分别检查已启用的账本。
- 监控库继续保存每月每渠道的原始费用。历史账本金额按渠道**当前归属**汇总：渠道改标签后，历史金额随之移动，但“全部”总额和原始归档费用不变，不必重读消费日志。未能确认归属的已删除渠道归“未分组”；已保存归属的删除渠道保留最后归属。
- 当前 New API 中没有渠道使用的标签不会显示，也不再独立告警；设置与历史仍保留，同名标签恢复后重新显示。“全部”和“未分组”始终存在。
- 余额与报警 API 可通过 `scope_id` 指定账本；省略则使用“全部”。

## 升级

升级前备份独立监控数据库和 `.env`。**不要清空数据库，也不要将迁移运行在 New API 原库。** 镜像启动时通过 `schema_migrations` 自动依次应用：

- `005_balance_scopes.sql`：建立分组账本，并将现有余额设置、报警、归档迁移至“全部”。
- `006_scope_visibility.sql`：记录分组是否仍存在于当前 New API 渠道标签中。

首次同步渠道清单后建立标签账本。升级前已删除的渠道如未保存标签，系统无法从 New API 恢复其原标签；不会自动猜测或修改消费金额。必要时可在**独立监控库**中核对其渠道 ID 与归属，不应修改 New API 消费日志。

将部署配置设为 `IMAGE_TAG=0.1.2`，然后执行：

```bash
docker compose -f compose.release.yml pull
docker compose -f compose.release.yml up -d
docker compose -f compose.release.yml logs --tail=100 statistics balance-worker
```

镜像：`ghcr.io/ilove323/new-api-statistics:0.1.2`。详细要求见[升级与备份](../upgrading.md)、[余额监控](../monitoring.md)和[API](../api.md)。

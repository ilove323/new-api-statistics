# New API Statistics 0.1.1

本版本强化用量明细分析，并将余额监控升级为可追踪、可筛选的逐渠道月度账本。
必须配合使用 PostgreSQL 的 New API 部署。

## 用量明细

- 用户、模型、令牌和分组筛选均支持搜索与多选，筛选仅作用于用户模型明细区域。
- 新增“令牌汇总 / 分令牌”和“模型汇总 / 分模型”模式；汇总模式会自动隐藏不适用的价格列。
- 明细列可以按需显示或隐藏，筛选与列设置不会改变 Excel 的固定报表结构。
- Excel 用户列旁新增独立的显示名列，没有显示名时保持为空。

## 开发者诊断

- `?dev=2` 保留缓存命中率、每百万 Token 金额，并在明细最后显示各失败状态码及次数。
- 失败日志按相同时间、用户、模型、令牌和分组筛选，支持模型与令牌汇总；只有失败没有消费的组合也显示。
- 诊断列不进入 Excel，失败请求不计入消费请求数、Token 或金额。

## 对外接口与认证变更

- 新增 `GET /statistics/api/balance`：每次实时计算本月消费，历史消费读取月度渠道归档；不缓存、不写报警、不发通知。
- JSON 包含站点、币种、总额度、累计消费、余额、阈值、使用百分比及带时区的检查时间。
- 报警接口迁移为独立的 `GET /statistics/api/alert`，仍执行检查并在满足条件时发送通知。
- 两个对外接口仅接受 New API **管理员 PAT**（users.access_token）的 Bearer 认证；不接受模型调用令牌或 Basic Auth。
- 返回的是站点预算，不是 PAT 所属用户的个人余额。网页和内部管理接口仍使用管理员账号密码。
- 原 /statistics/api/balance/alert 调用方必须更新路径与认证；网页状态接口已迁至 /statistics/api/balance/status。
- 只读账号需可读取 users.access_token，无需 tokens 表或新增密钥表。

## 测试修复

- 修复 PostgreSQL SQL 集成测试的模拟 logs 缺少 group 字段问题。
- 增加失败码聚合、PAT 认证边界、实时余额无缓存及无通知副作用测试。

## 余额与渠道归档

- 监控库按“月份 + 渠道 ID”保存所有渠道的原始消费金额，包括已禁用渠道。
- 渠道 ID 作为稳定标识；同 ID 改名会同步库存和历史归档名称。
- 从 New API 删除的渠道仍保留最后名称并标记为“已删除”，可继续参与历史费用筛选。
- 消费渠道勾选只影响月度展示、累计消费、剩余额度和报警，不删除底层渠道归档；重新勾选后历史费用立即恢复。
- 恢复“追溯历史计费”：连续确认后读取完整历史渠道数据，先展示逐月新旧金额和差额，最终确认后才覆盖归档。查询失败、整个区间无消费数据或预览后数据变化时不会写入。

## 通知渠道

- 钉钉通知改为群聊自定义 Webhook 机器人，支持关键词安全策略和可选 HMAC-SHA256 加签。
- Webhook URL、钉钉加签密钥和飞书 App Secret 均加密保存在独立监控库，API 不回传凭据。
- 飞书企业自建应用通知保持不变。

## 从 0.1.0 升级

升级前备份独立监控库、部署 `.env` 和 `NOTIFICATION_ENCRYPTION_KEY`。将镜像版本改为：

```ini
IMAGE_TAG=0.1.1
```

然后更新服务：

```bash
docker compose -f compose.release.yml pull
docker compose -f compose.release.yml up -d
docker compose -f compose.release.yml logs --tail=100 statistics balance-worker
```

启动时自动执行以下监控库迁移：

- `002_balance_usage_channels.sql`：保存不计入余额的渠道 ID。
- `003_balance_channel_archives.sql`：增加渠道库存和逐渠道月度归档。
- `004_dingtalk_webhook_upgrade.sql`：为已发布的 `0.1.0` 安装创建钉钉 Webhook 配置。

首次余额检查或保存余额设置时会尝试把已有月度总额拆分为逐渠道明细。New API 消费日志必须
仍覆盖累计起始月份；自动拆分检测到当前历史金额低于旧归档时会失败并保留旧数据。管理员可以
使用“追溯历史计费”查看逐月差额，在确认数据完整后主动覆盖。

旧钉钉企业应用的 Client ID、Client Secret、Robot Code 和会话 ID 不能转换为 Webhook。
若升级前选中了旧钉钉渠道，迁移会关闭通知并要求管理员重新填写群机器人 Webhook URL；
飞书配置及余额数据不受影响。

## 安装与兼容性

镜像：`ghcr.io/ilove323/new-api-statistics:0.1.1`。

下载本 Release 的 `compose.release.yml`、`.env.example` 和 `nginx.conf.example`，按
[部署文档](https://github.com/ilove323/new-api-statistics/blob/v0.1.1/docs/deployment.md)完成配置。
本版本要求 New API 使用 PostgreSQL，并可只读访问 `logs`、`users`、`options` 和 `channels`；
完整字段要求见[兼容范围](https://github.com/ilove323/new-api-statistics/blob/v0.1.1/docs/compatibility.md)。
